components.json

Project configuration for the CLI, written by init.

{
  "$schema": "https://shadcn-aurelia.com/schema.json",
  "style": "default",
  "prefix": "ui",
  "tailwind": {
    "css": "src/styles/globals.css",
    "baseColor": "zinc"
  },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib"
  },
  "registry": "https://shadcn-aurelia.com/r"
}

style

The registry style to pull components from. Currently default is the only style; a new-york port may follow upstream later.

prefix

The custom element prefix. Registry sources use ui (<ui-button>); the CLI rewrites tags and the element name strings in TypeScript when you pick something else, so prefix: "acme" gives you <acme-button> throughout. Pick it once at init — changing it later means re-adding components (your prefix is applied at copy time, not at runtime).

tailwind.css

Path to the stylesheet containing @import "tailwindcss". The theme file (shadcn-aurelia.css) is written next to it and imported from it.

tailwind.baseColor

The base gray palette for the theme variables (zinc by default).

aliases

Where add writes files and how imports are rewritten. Registry sources import from @/registry/default/ui/…; those become your ui alias. Items of type lib (like cn) go to the lib alias. The aliases must be resolvable in your project — init checks that @/* maps to src/* in tsconfig.json and Vite. Any wildcard alias from your tsconfig paths works here, not just @/… — see the Monorepos section of Installation for pointing the aliases at a shared workspace package.

AliasDefaultReceives
ui@/components/uicomponent folders (button/, dialog/, …)
lib@/libutilities (cn.ts, shared types)
components@/componentsnon-ui components (blocks reference this)

registry

Base URL (or local directory) the CLI fetches from. Items resolve as <registry>/styles/<style>/<name>.json, the index as <registry>/index.json.
