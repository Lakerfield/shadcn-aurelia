Differences from shadcn/ui

The styles, anatomy and data-slot contract are ported 1:1. What differs is what has to differ: React idioms become Aurelia idioms.

Custom elements with a prefix

React components (<Button>) become Aurelia custom elements (<ui-button>). The ui- prefix is configurable per project via components.json. Elements render in the light DOM — no shadow roots — so Tailwind utilities, your global stylesheet and the theme variables apply directly. These are Aurelia components, not standalone web components; they need the Aurelia runtime.

Slots instead of children

JSX children become au-slot projection. Composition looks the same in practice:

<ui-card>
  <ui-card-header>
    <ui-card-title>Title</ui-card-title>
  </ui-card-header>
  <ui-card-content>…</ui-card-content>
</ui-card>

One consequence: projected content mounts after the host's bound() lifecycle. The components account for this internally; it only matters if you modify them.

Events instead of callbacks

React callback props (onOpenChange) become DOM CustomEvents with kebab-case names, listened to with .trigger. The payload is in $event.detail: 

<ui-dialog open-change.trigger="onOpenChange($event.detail)">…</ui-dialog>
<ui-checkbox checked-change.trigger="save($event.detail)"></ui-checkbox>

Two-way binding instead of controlled state

The controlled/uncontrolled split disappears: leave a bindable alone for uncontrolled behavior, or bind it (two-way by default on state bindables) to control it: 

<ui-collapsible open.bind="isOpen">…</ui-collapsible>
<ui-select value.bind="fruit">…</ui-select>

No asChild

Radix's asChild render delegation has no Aurelia equivalent. Instead, trigger and wrapper elements are host-styled: classes you put on the element merge with the component's own (via cn()), and structural parts carry data-slot attributes so upstream selectors keep working. Where shadcn/ui writes <PopoverTrigger asChild><Button /></PopoverTrigger>, you write: 

<ui-popover-trigger>
  <ui-button variant="outline">Open</ui-button>
</ui-popover-trigger>

Zag.js instead of Radix

Interactive behavior comes from Zag.js state machines behind a facade in @shadcn-aurelia/primitives. Copied components import only from that facade — keyboard maps, ARIA wiring and data-state attributes match the Radix/WAI-ARIA APG behavior shadcn/ui users expect (see Accessibility). Primitives may migrate to native implementations over time without changing your components.

Context via DI

React context becomes hierarchical dependency injection: a root element (e.g. <ui-sidebar-provider>) registers state that descendants resolve. This is internal to the components — as a consumer you just nest elements.

What's identical

  • cn() (clsx + tailwind-merge) and CVA variant definitions.
  • All Tailwind classes, CSS variables and the theming contract — upstream themes drop in.
  • data-slot, data-state, data-side attributes.
  • The registry/CLI model, including components.json and registry item schema compatibility.

Not (yet) ported

drawer (vaul's drag gestures) is deferred; everything else from the shadcn/ui v4 inventory is available — including the chat suite (attachment, bubble, message, message-scroller, marker), where message-scroller runs on a native engine in @shadcn-aurelia/primitives ported from upstream's own primitive.
